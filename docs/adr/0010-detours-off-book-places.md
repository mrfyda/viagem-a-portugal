# Detours — off-book places the author visited

The map models Saramago's book (a **Place** is an entry in the toponymic index,
the join key for markers, Routes, Visits and progress) plus the **Traveler**'s
Visits. We also want to show places the author actually visited that are *not*
in the book — e.g. the Mazouco rock engravings, discovered 1981, after
Saramago's 1979 journey. We model these as **Detours**: display-only points
generated by `blog-sync` (from a `detours:` front-matter block) into
`apps/map/src/data/detours.json`, rendered as a distinct solid slate marker
(outside the amber/green and chapter palette), never on a Route, not Visit-able,
and excluded from the journey progress count. A Detour is selected/deep-linked via its own `?detour=` query param (it
has no `indexName`).

## Considered options

- **Overload `Place` to include off-book locations** — rejected. `Place` = index
  entry is the join key for the entire model; off-book entries would pollute the
  "of 579" denominator and render as indistinguishable 0-mention towns.
- **Hand-author `detours.json` directly** (the `corrections.json` /
  `journey-overrides.json` precedent) — rejected: it duplicates the post's
  note, photo and link, which can drift from the post that also narrates the
  Detour. Generating from the post keeps a single source of truth and reuses
  `blog-sync`'s existing CI drift gate.
- Detours use a **separate `detours:` front-matter key**, not the
  index-validated `places:` — a Detour is deliberately *not* in the book index,
  so it must skip that validation rather than fail the build.

## Consequences

- A Detour cannot be marked visited or counted toward progress. If per-Traveler
  off-book places are ever wanted, that is a new feature (its own sync table).
- Detours are kept out of the generated, book-derived `book-index.json` /
  `locations.json`; they live only in the generated `detours.json`.
- `blog-sync` now reads two front-matter keys: `places:` (validated against the
  index) and `detours:` (not validated).
